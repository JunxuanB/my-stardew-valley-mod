# 0.6.5 对白与切蛋糕结果

本版针对用户提交的两份 `ContentLoadException: Unable to parse string path` 日志及蛋糕结果交互要求。完成 API 核对、编译和打包，没有启动游戏做自动 QA。

## 对白报错

原版 `NPC.setNewDialogue(string)` 的参数是翻译资源路径，不是对白正文。之前将莱纳斯的问候、送花回复直接传入，游戏因此尝试把整句话当作路径加载。

现在先创建 `Dialogue(speaker, null, text)`，再交给 `setNewDialogue(Dialogue)`。这样仍使用原版人物头像和对话框，但直接显示正文。格斯的新增评价也使用同一修正。

## 手动查看与结算

- 两人完成落刀后进入结果页，显示红色第一刀、蓝色第二刀、玩家名字和间距。两刀重合时仍能分别看到上下标记。
- 删除 8 秒倒计时及自动关闭。结果持续保留，直到本人点击“确认”或右上角关闭，也可用 Enter/空格/手柄 A 确认、Esc/B 关闭。
- 完成落刀前的 Esc/B 仍取消挑战；进入结果后则表示已看完结果，不算放弃奖励。
- 本人手动确认后才显示格斯评价并领取本人的花束。两刀几乎重合会夸“默契十足”，比较接近会夸配合，较远则说一起分享的蛋糕一样甜；随后说明花束数量并说“欢迎再来一起切蛋糕！”
- 发奖标准不变：差距不超过 0.15，每人 2 束，否则每人 1 束。每位玩家每局只结算一次，重复点击或重复消息不重复发奖。
- 两人的确认相互独立。一人关闭结果不会强制关闭另一人的结果，也不会要求另一人立刻确认。双方都看完后，可再次互相邀请。
- 已看完的一方解除项目占用，可以继续游园；另一人离场/断线时，仍在场玩家的已完成结果不会被强制收起。未完成落刀的挑战仍按原规则取消。

## 请手动复验

1. 双方更新至 0.6.5，进入一届新节日。没有手捧花时右键莱纳斯，再分别送第一束、第二束，确认普通对白和两次回复都能显示、不再刷上述错误。
2. 完成切蛋糕后等超过原来的 8 秒，结果应保留且没有倒计时，也还没有播放格斯评价。
3. 一边点击“确认”，检查格斯评价、1 或 2 束奖励和“欢迎再来”；另一边仍留在双刀结果页。
4. 另一边用右上角关闭或 Esc/B 查看评价并领奖。交换先后手再玩，分别验证键盘 Enter/空格和手柄 A。
5. 连续点击不会重复领花；两人均确认后可以重新邀请。第一人落刀、第二人未落刀时取消，仍不发奖。

关闭两个游戏窗口后运行根目录 `Launch-AnniversaryQA.cmd` 加载新版。仍保留第一年可用 `/yea`、固定节日从第二年开始等已有规则。
